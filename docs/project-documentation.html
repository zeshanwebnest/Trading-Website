Vault Easy's site is two things working together: a marketing site describing the brokerage, and a real client onboarding system — registration, KYC document collection, and admin-reviewed verification — built on plain PHP and MySQL.

It's deliberately framework-free on both ends: vanilla HTML/CSS/JS for the front end, vanilla PHP for the back end. The backend stack (PHP + MySQL) was chosen specifically because the project's next planned phase is a conversion into WordPress, which runs on the same stack — so this work carries forward rather than being thrown away later.

How the pieces fit together

Architecture

The front end never talks to the database directly — every read or write goes through a PHP endpoint under /backend, called via fetch() from assets/js/account.js.

Two things make the verification workflow secure rather than cosmetic:

  • Two separate session keys — $_SESSION['applicant_id'] and $_SESSION['admin_id'] — so an applicant session can never pass an admin check.
  • Every admin endpoint checks require_admin() first, before touching any data. That function call is the actual security boundary — not anything the front end shows or hides. See backend/admin-decision.php.

Uploaded documents (CNIC images, proof of address) are stored under backend/uploads/<field>/<random-hex>.<ext>, a directory with its own .htaccess denying all direct web access. The only way to ever view one is backend/file.php, which checks the requester is either the owning applicant or a signed-in admin before streaming the file.

What's actually built

Key features

Marketing site

  • Fully responsive dark/gold premium fintech theme
  • Animated hero with a live-scrolling candlestick chart (canvas-drawn) and synced price/24h stats
  • Pure-CSS mobile navigation — works even if JavaScript fails to load
  • Licensed stock photography throughout; floating WhatsApp contact button site-wide

Registration (open-account.html)

  • 5 steps: Personal Info → Identity/CNIC → KYC Profile → Bank Details → Documents & Review
  • CNIC auto-formats as you type (12345-1234567-1)
  • File uploads validated server-side by actual file content (finfo_file()), not filename or claimed type
  • Full client + server validation (age 18+, CNIC format/expiry, email, phone) — server-side is the real boundary
  • Success modal with close button, broker-name note, and a cancellable auto-redirect to the mobile app download

Client dashboard (dashboard.html)

  • Real login against the applications table
  • Profile overview with CNIC/account number masked for display
  • Verification status tracker (Submitted → Under Review → Verified/Rejected), with rejection reason shown when applicable
  • Document list with auth-checked "View" links
  • Edit profile for basic fields — CNIC/bank details are intentionally not editable here

Admin panel (admin.html)

  • Separate admin login, distinct from client accounts
  • Filterable verification queue (All / Under Review / Verified / Rejected)
  • Full review screen: personal info, CNIC + both images inline, KYC profile, bank details, supporting documents
  • Approve (one click) or Reject (reason required, shown to the applicant)
  • Review history — who decided, and when
Getting into the system

Admin: signing in

1

Go to the admin panel

Navigate to http://localhost/vaulteasy/admin.html locally (or the production URL once deployed).

2

Enter credentials

Default account created by backend/seed-admin.php: username admin, password ChangeMe123!.

3

Session starts

Signing in sets $_SESSION['admin_id'], checked by every admin endpoint. "Sign Out" destroys it entirely.

Change the default password

This is a seed value, not a real credential. There's no in-app "change password" screen yet — update it via phpMyAdmin or a small script calling password_hash() against admin_users.password_hash.

There is intentionally no self-service admin registration. New admin accounts are created directly in the database, never through a public form.

The actual verification workflow

Admin: review, verify, and approve

1

Open the queue

Every submitted application, newest first — name, email, date, status, and reviewer if any. Filter with the pill buttons.

2

Click into a review

See personal info, CNIC number plus View CNIC front / back (opens the actual uploaded image), KYC profile including the PEP flag, bank details, and supporting documents.

3

Decide

Approve — one click, sets status to Verified immediately. Reject… — requires a written reason, stored and shown to the applicant so they can fix and resubmit.

4

It's logged

Every decision records the reviewing admin's ID and a timestamp (reviewed_by, reviewed_at). Once decided, the panel shows history instead of action buttons.

Getting it running

Running the project locally

# 1. Install XAMPP (PHP 8.2 + MySQL + Apache)
winget install ApacheFriends.Xampp.8.2

# 2. Point Apache at this project folder — add to httpd.conf:
Alias /vaulteasy "C:/path/to/this/project"
<Directory "C:/path/to/this/project">
    Options Indexes FollowSymLinks
    AllowOverride All
    Require all granted
</Directory>

# 3. Start services
C:\xampp\mysql_start.bat
C:\xampp\apache_start.bat

# 4. Import the schema
mysql -u root < backend/schema.sql

# 5. Create the first admin (visit once in a browser, then delete the file)
http://localhost/vaulteasy/backend/seed-admin.php

# 6. Browse the site
http://localhost/vaulteasy/index.html

The whole site must load through Apache this way — not as a file:// path — since PHP only executes when served by a web server.

Running in production

Not deployed anywhere yet

This currently only runs on localhost via XAMPP. Nothing below has been done — it's the checklist for whenever real hosting is ready.

  • Serve over HTTPS; set 'secure' => true in the session cookie params in backend/config.php
  • Move DB_USER/DB_PASS out of source control; use a dedicated MySQL user, not root with no password
  • Add rate-limiting to login.php and admin-login.php
  • Add real email notifications on approve/reject
  • Change the default admin password
  • Confirm the production server also blocks direct access to backend/uploads/
  • Decide on the WordPress conversion before investing further in this stand-alone version, if that's still the plan
